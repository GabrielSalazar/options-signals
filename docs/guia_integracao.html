b3_ticker_loader.py

Módulo de varredura dinâmica — substitui a lista estática de ~20 ativos por toda a B3 filtrada por liquidez.

Visão Geral

O scanner atual itera sobre uma lista hardcoded de ~20 tickers em config.py. Este módulo expande isso para toda a B3 (~400+ ativos), aplicando um filtro de volume antes de passar os tickers para o analisar_ativo().

💡
Na prática: de ~400 ativos listados, ~80–120 passam no filtro de 1M de volume diário. O pipeline do seu core_engine.py já rejeita ativos com volume insuficiente na Etapa 3 — este módulo faz o pré-filtro para economizar tempo e chamadas de API.

DEPOIS — dinâmico, toda a B3

Pythonscanner_opcoes_b3_v3.py (depois)
# ✅ Import no topo do arquivo (junto com os outros imports)
from b3_ticker_loader import carregar_tickers_b3

def main():
    # ── Etapa 0: Carregar tickers dinamicamente ────────────────
    logger.info("Carregando tickers da B3...")
    tickers_base = carregar_tickers_b3(
        min_volume=1_000_000,   # mesmo filtro do core_engine Etapa 3
        top_n=150,             # top 150 mais líquidos (None = sem limite)
        usar_api_b3=True,       # tenta API oficial primeiro
        usar_lista_curada=True,  # complementa com lista curada
    )
    TICKERS = [f"{t}.SA" for t in tickers_base]
    logger.info(f"✅ {len(TICKERS)} ativos para scan")

    # ── Loop de análise (igual ao atual) ──────────────────────
    sinais = []
    for ticker in TICKERS:
        try:
            sinal = analisar_ativo(ticker, interval="1d")
            if sinal:
                sinais.append(sinal)
                enviar_telegram(sinal)
        except Exception as e:
            logger.error(f"Erro em {ticker}: {e}")

Fallback & Tratamento de Erros

⚠️
API B3 fora do ar? O módulo captura a exceção, loga um warning e cai automaticamente para a lista curada de 60+ tickers. O scanner continua rodando sem interrupção.
⏱️
Tempo estimado de execução: Com top_n=150 e filtro de volume ativo, o carregamento leva ~45–90 segundos (batch de 20 tickers × delay de 1s). Execute uma vez por sessão e reuse a lista no loop de scan.

Modo Produção vs Modo Rápido

PythonConfigurações recomendadas
# Modo Produção — máxima cobertura (roda 1x/dia)
tickers = carregar_tickers_b3(
    min_volume=1_000_000,
    top_n=None,          # sem limite — todos os líquidos
    usar_api_b3=True,
)

# Modo Rápido — scan intraday (a cada 15 min)
tickers = carregar_tickers_b3(
    min_volume=2_000_000,  # mais restrito = mais rápido
    top_n=80,
    usar_api_b3=False,    # só lista curada, sem HTTP extra
    filtrar_volume=False, # pula yfinance — confiar na lista curada
)
